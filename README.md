# AI 协同开发脚手架

*English: An AI-executed setup guide for a new or in-progress code project. It sets up three things only — a handover trail any AI can pick up from, hard delivery rules for code (approval gates, evidence, review), and machine-checked limits that keep docs from bloating. Multi-window AI coordination lives in the companion "lead-session collaboration playbook".*

> 版本 v2.0.1。多个 AI 窗口怎么协作看[《总控协作手册》](https://github.com/rainman016/solo-ai-team-playbook/blob/v3.2/README.md)，代码项目怎么交付看这里；衔接细节见 [衔接说明.md](衔接说明.md)。

## 1. 一句话

开新代码项目，或接手一个在做的项目时，把“搭建指令”交给 AI：几分钟搭好**交接载体、代码交付硬规则、文档上限**，然后从“梳理项目架构”开始干活。任何 AI 读三份文件就能接手。

## 2. 它解决什么问题

| 问题 | 平时的样子 | 脚手架怎么防 |
|---|---|---|
| 代码写完就当完成 | AI 说“改好了”，一跑就坏 | 回报带版本号和证据路径，没看过的写“未验证”；每个候选先跑一条全量检查命令；高风险改动另一个会话独立复核 |
| 一句“可以”被当成推送许可 | 你同意方案，AI 理解成可以上线 | 推送、合并、部署各有固定口令，一道一句；“可以／继续／好的”都不算 |
| 几条线互相覆盖 | 两个 AI 改同一批文件，或在正式目录里改 | 一线一文件夹一分支，登记后才施工；共享部分先合 |
| 换个窗口就忘了前面 | 新窗口翻聊天、重跑检查 | 进度写在固定三份文件里，新窗口读完就能接上 |
| 文档越写越多 | 规则、记录、过程稿堆成山 | 只准建固定几种文件；上限写成数字，提交时由脚本检查 |

## 3. 和《总控协作手册》怎么分工

| | 手册 | 脚手架（本包） |
|---|---|---|
| 管什么 | 多个 AI 窗口谁说了算：角色、派单、回报、通知、换窗、定档、并行 | 一个代码项目怎么交付：交接载体、门禁、证据复核、文档上限 |
| 什么时候装 | 同时开 2 个以上 AI 窗口 | 有源码仓库的项目 |

手册已有的内容，脚手架只放**链接**（固定到手册的发布版本），不复制；门禁、授权、密钥这类硬规则**留在项目里**，因为 Codex 等施工工具读不到你本机的全局规则，也未必能联网。两个都能单独用，也能一起用；冲突以项目里生成的规则为准。

## 4. 怎么用

对 AI 说：“照 `搭建指令.md` 给这个项目搭结构。”（如果你是 AI：接下来读 `搭建指令.md`，照它执行。）它先判断新项目还是已有项目。

**新项目**：一次问完 8 个起步问题（本机没配 git 身份时多 1 条），每条带推荐，你只答一轮 → 按默认布局建目录、规则和只读基线，**本地提交，不推送** → 自动开出任务 01“项目架构梳理”，你逐项确认后才开第一条施工线。

| # | 起步问题 | 决定什么 |
|---|---|---|
| 1 | 项目名和英文简称 | 文件夹名、分支前缀 |
| 2 | 源码仓库已有还是新建 | clone 还是新建 |
| 3 | 技术栈、源码目录、有没有全量检查命令 | `AGENTS.md` 的检查命令 |
| 4 | 上线了没有、有没有登录、有没有持久数据 | 轻量档还是完整档 |
| 5 | 有没有另一个 AI 工具施工 | 没有就总控兼任，复核另开独立会话 |
| 6 | 合并权在谁 | 个人模式还是团队模式 |
| 7 | 治理记录要不要推私有备份仓库 | 治理区要不要配远端 |
| 8 | 会不会多窗口协作 | 会就提示另装手册 |

**已有项目（嫁接）**：只读盘点分支、工作树、PR、在途任务、已有规则和 CI，出盘点表和位置映射表给你确认（**不搬、不改名**）；在途任务登记进总览，和已有规则冲突的条目逐条列给你；仓库自带的治理（CI、仓库里的 `AGENTS.md`、分支保护）**优先**。嫁接**不改你的源码仓库**里被版本管理的文件和仓库配置：规则只放治理区（默认建在仓库外面，与仓库平级），撤回时只删治理区新增的文件和 AI 新建的施工文件夹、分支。这条只管搭建阶段，规则生效后，已授权的任务在登记过的施工文件夹里正常改代码。

**规则什么时候开始管用**：搭完你说一句“确认规则生效”，AI 记下提交号。在那之前，新项目只做搭建和任务 01，已有项目原有工作照原来的做法。

## 5. 搭完长什么样

四类位置：**治理区**（规则和任务记录，只放文字）｜**正式工作区**（源码仓库，固定检出主线，不在这里开发）｜**施工区**（一线一文件夹一分支，登记后才施工）｜**只读基线**（主线的只读副本）。

```text
<项目根>/                          ← 治理区（一个只本地提交的 git 仓库）
├─ AGENTS.md   CLAUDE.md           ← 入口：路由、硬边界、口令；CLAUDE.md 一行 @AGENTS.md
├─ 项目文档/
│  ├─ 交付规则.md  文档规则.md  岗位速查.md
│  ├─ 工程手册/   复核结论模板、推送前扫描（.md/.sh）、文档上限.json、文档体检.sh
│  └─ 任务记录/   当前任务总览.md、协作治理/当前状态.md、模板/（施工指令、施工回报）、任务01 …/
├─ main/                           ← 正式工作区
└─ worktrees/<简称>-main/          ← 只读基线
```

搭进项目的 17 个文件合计 ≤ 40,000 字，必读三件 ≤ 6,000 字。文件名用中文，`AGENTS.md` 开头写明“用 UTF-8 读”；源码仓库里不加文件。

## 6. 三件事

### 交接载体

每次开工只读三件：`AGENTS.md` → 《当前任务总览》（任务表、持续授权、施工区登记、迁移号、最近完成）→ 当前任务的《当前状态》（固定六段，含唯一下一步）。换窗、换工具前先改状态，接手的核对分支、提交、未提交改动再继续。只靠文件和 Git。

### 代码交付硬规则（`交付规则.md`）

- **门禁**：不可逆的动作，每一道都要你单独说口令，只由总控执行。
- **证据**：回报只认文件；候选变了先看完整差异再按影响补验；失败先分类；高风险改动（登录权限、数据库迁移、公开接口、门禁类规则等）由非实施者独立复核。
- **检查命令**：每个项目一条全量命令，第 1 道门禁就是对精确版本跑它通过；没有的，任务 01 第 8 项产出“检查现状与缺口”，第一条施工线补齐，补齐前不开功能施工（可先用最小命令，你可书面豁免）。
- **并行**：完整档最多 3 条线（一条做集成），轻量档 2 条；共享部分先合，迁移号统一分配，用合并不用变基，不改写历史、不强推。
- **推送前扫描**：每类特征单独跑、看退出码；没跑成不算通过；有二进制文件时由你看清单后才放行。
- 工程实现四条约束只留 4 行：不堆没依据的防御、入口校验内部流转、不提前抽象、只在能处理处捕获异常且不静默吞错。

### 文档防膨胀

任务目录只准放固定几种文件；`文档上限.json` 写所有上限，`文档体检.sh` 挂在治理区提交关口，必读三件超限、14 条硬规则关键句缺失、`AGENTS.md` 指到的文件不存在会拦提交，其余提醒；收口是一道门，过程稿移进归档、体检通过才能标“已交付”。超限只能移走，不许删没处理完的反馈和授权。

## 7. 门禁一览

| | 个人模式·完整档（6 道） | 个人模式·轻量档（4 道） | 团队模式 |
|---|---|---|---|
| 口令 | 自动验证 → 手测 → “确认发布候选” → “确认合并” → “确认同步远端” → “确认部署” | 自动验证 → 手测 → “确认合并” → “确认同步远端” | 自动验证 → 手测 → “确认发布候选”（总控推分支、建 Draft PR） |
| 之后 | 你说口令，总控执行 | 同左 | 完整 CI、验收、合并、发布归仓库负责人；AI 不合并、不推主线 |

怎么选模式：只有你能往主线合 → 个人；主线有保护、要别人审批、属于团队 → 团队；拿不准选团队。六道互不替代；走 PR 合并要同时有“确认合并”和“确认同步远端”；远端是空的时，首次接入远端的授权要写明含“推送主线的空初始提交”。

## 8. 两档对照

| | 轻量档 | 完整档 |
|---|---|---|
| 什么时候用 | 上线、登录、持久数据三项都没有 | 任一项有，或拿不准 |
| 门禁（个人） | 4 道 | 6 道 |
| 独立复核 | 只有改门禁规则时 | 高风险清单里的全部 |
| 同时几条线 | 2 | 3 |
| 目录和规则文件 | 相同 | 相同 |

升档由总控提出、你确认；不自动升。

## 9. 怎么判断有没有用

**搭建验收**：空文件夹搭虚构项目只答一轮问题、没有空文件；新开 Claude 窗口和 Codex 线程只靠自动加载都答得对“在哪施工、要哪些口令、第一个任务、上一棒到哪、下一步”；嫁接到模拟的在途项目时已有分支和文件一个不搬不改名；团队模式里 AI 没有合并和推主线的权限；体检脚本放行和拦截各造一例；凭据和私有词扫描 0 命中。

**试运行**（接入后 3 件中档任务或 2 周）：越权 0 次；“说通过、事后被推翻”0 次；每份回报有版本号和证据路径；返修超过 2 轮 0 次；新窗口只读三件就能继续；两线撞同一批文件 0 次；规则文件体检一直通过。总控每件任务收口时记三个数（拍板、返修、越权或被推翻），期满由独立 AI 读总览打分，总控不自评。

## 10. 升级与撤回

- **复制进项目，不引用原文件**：脚手架更新不会悄悄改到你的项目；《当前状态》记脚手架版本。
- **升级**：总控对照 [CHANGELOG.md](CHANGELOG.md) 列差异，你确认后再合进项目。v1.0 → v2.0 的做法在 CHANGELOG 里。
- **撤回**：按搭建时记下的新增清单，只删脚手架新增的内容；你原有的笔记和后来写的代码都保留。
- 门禁类规则的修改（两档都一样），复核通过前不生效。

## 11. 不包括什么

业务代码和技术栈模板；推送、建远端、部署的执行（脚手架只定门禁，执行等你说口令）；密钥（不读、不存、不生成）；多窗口怎么协作（在手册）；调研、可行性这类专项做法。

