# 复核结论模板

> 给复核者填的一页纸模板，不是规则；门禁仍以《交付规则》为准。基于候选的完整差异和证据填写，不以实施者的自评代替复核。复核者不能是实施者。

**任务与风险**：任务名称；小／中／大档，以及判为高风险的依据。

**复核对象**：施工文件夹、分支、精确候选版本、比较基点；治理区材料的精确提交或文件。有未提交改动要说明。

**结论**：通过 ／ 有条件通过 ／ 不通过。用一句话说明，用户路径能不能达到本轮约定的交付面。

| 核对项 | 结论与证据位置 |
|---|---|
| 已确认的范围、契约和完整差异一致 | |
| 影响面、外部依赖、数据边界 | |
| 自动验证和本机检查摘要覆盖了这个候选 | |
| 对抗用例和异常恢复 | |
| 手测：已通过／待测／不适用（理由） | |
| 例外、文档事实、回退方式 | |

**必须修正**：只列会阻断当前约定结果的事项，写明位置、实际影响、最小修正；没有就写“无”。

**建议**：可选的改进和取舍，不混同于交付阻断。

**为什么这样设计、放弃了什么**：一句话。

**唯一下一步**：返修 ／ 手测 ／ 取得哪项动作的授权。只记录已核实的授权范围，**不能用“复核通过”代替用户的门禁授权**。

**复核者与日期**：写明没参与本次实施；本结论对应上面的精确候选。
