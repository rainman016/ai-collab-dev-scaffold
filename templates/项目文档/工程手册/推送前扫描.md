# 推送前敏感扫描

> 说明材料，不是规则；规则见 SOP 和 `AGENTS.md`。作用：把一个分支推到远端之前，确认**这次推送会让远端新增的全部提交**里没有凭据，并且推往的就是核实过的私有仓库。代码文件部分按 MIT 授权。

## 要点

- **扫哪里**：先锁定待推分支此刻的精确提交号（OID），只认它，不看当前检出的是哪个分支；再直接问推送地址“远端现在有哪些分支和标签”，扫从这个 OID 能到达、而远端还没有的全部提交。远端还没有这个分支（包括首次接入远端、推只含空提交的主线）也一样算：就是该分支全部历史减去远端已有的。
- **扫什么**：按凭据的格式特征匹配——私钥头、常见令牌前缀加足够长度、地址里内嵌的密码。**不要**按“密码”“Key”这类普通词扫，会满屏误报，最后没人看。
- **每一类特征单独跑**，看退出码：`0` = 有命中（停止），`1` = 没命中，其他 = 扫描本身出错（**按不通过处理，停止**）。
- **先自检**：用一个拼接生成的样例，确认匹配规则本身能识别。
- **只输出文件名或提交号**，不输出命中的内容，避免把凭据又打印出来；输出远端地址前，先把地址里的账号口令换成 `***`。
- 文档里不要写完整的凭据样例（会被扫描命中）；自检样例用拼接生成。
- **“扫了没命中”“没扫到”“没跑成”分开报告**。没跑成不算通过；有没扫到的文件，也不能说全部通过。
- **推往哪里要和查的是同一个仓库**：先核对实际推送地址的主机、账号、仓库名和配置的仓库一致，再核实它是**私有**仓库；对不上就拒绝。
- 命中就停止推送，由用户处理并确认后重扫。

## 能覆盖什么、覆盖不到什么

- **覆盖**：每个要扫的提交里、整个仓库的全部**文本文件**（不论当前在哪个子目录运行）；以及每个要扫的提交的**提交说明全文**（同样 6 类特征逐类扫，命中只输出提交号和类别）。
- **二进制文件扫不了内容**：git 判为二进制的文件（含 UTF-16 编码的文本、图片、压缩包等）里就算有凭据也认不出来。脚本把它们单列为“未扫描”，**默认停止**（退出码 1），由用户逐个确认后放行（见下节）。
- **覆盖不到、也不单列的**：作者和提交者信息（姓名、邮箱）；文件路径名本身；子模块里的内容（属于另一个仓库）；Git LFS 托管的大文件本体（仓库里只有指针）；标签说明（脚本只推分支，不推标签）。这几类用到时由人工把关。

## 二进制文件怎么放行

选的是**要求用户确认**，不是一律拒绝：项目里常有图标、图片这类必须入库的二进制文件，一律拒绝只会逼人绕开扫描。为了让确认落到实处：

- 脚本列出这批二进制文件，并给出一个**指纹**（由这批文件的确切内容算出）。
- 用户看过清单、确认不含凭据（或把它们移出这次推送）后，才加 `--binary-ok=<指纹>` 重跑。**指纹由用户确认后才能填，AI 不得自行填写。**
- 文件有增减或内容一变，指纹就变，旧指纹作废，要重新确认。
- 放行后的结果写明“另有 N 个二进制文件没扫内容，已由用户按指纹确认”，不写成全部通过。

## 脚本

脚本在同目录的 `推送前扫描.sh`（bash，MIT）。上面的要点它都做了；用法和退出码写在脚本开头：

- 开头有 4 个占位符（仓库路径、远端名、分支名、仓库全名）：配置远端时填，没填完脚本拒绝运行（退出码 2）。仓库全名写 `账号/仓库名`（默认 github.com）；别的主机写 `主机/账号/仓库名`。
- 默认只扫描、不推送；加 `--push` 才推送。**推送本身是门禁动作，先有用户的授权，再加 `--push`**。
- 推送地址取 git 实际会用的那个（已按 `insteadOf`／`pushInsteadOf` 改写）；只支持一个推送地址。用 SSH 别名（`~/.ssh/config` 里自起的主机名）的地址会被判为对不上，远端地址要写真实主机名。
- 加 `--push` 时依次：用 `gh` 核实配置的仓库是私有、且查到的就是这个仓库（改过名、发生跳转的也拒绝）→ 复核扫描之后分支 OID、推送地址、远端现状都没变 → 把**同一个 OID** 推到核实过的地址 → 推完核对远端分支确实是这个 OID。任何一步不对都停止（退出码 2）。
- 推送直接推往核实过的地址，本地的远端跟踪分支不会跟着更新；需要时推完再 `git fetch`。
- 只扫描、读不到远端时（没配远端、离线），按首次推送扫该分支全部历史——只会多扫，不会少扫；加 `--push` 时读不到远端就是没跑成。
- 脚本退出码：`0` = 通过；`1` = 有命中，或有没确认的二进制文件；`2` = 没跑成或核实不通过（不算通过）。
- 一次推送的提交特别多时，列出的提交号可能超过命令行长度上限，脚本会按“没跑成”处理，不会假装通过。
- 在 Windows 的 Git Bash 下，脚本换行是 CRLF 也能跑。

## 为什么要写得这么死

“模式以 `-` 开头会被当成命令选项而报错”“一类特征没跑成却被当成没命中”“二进制文件被跳过却报了通过”，这几种错都会让扫描**看起来通过了**。“扫的是当前检出的分支、推的是另一个分支”“查的是一个私有仓库、推的是另一个公开仓库”，则会让通过的扫描**护错了对象**。所以：锁定要推的那个提交号、核对推往的地址、每类单独看退出码、出错一律不通过、先自检、扫不到的单列出来。
