# 问题卡：上下文与文档失控

## 什么时候翻这张

- 接手一个任务，要先读一大堆历史；
- 同一个状态写在好几份文档里，互相对不上；
- 一个功能有好几个长期存在的分支或施工文件夹；
- 说不清“现在是哪个版本、PR 在哪、下一步是什么”；
- 旧指令、旧版本号被当成了现状。

## 先自问

1. 动态的状态是不是**只有一份**？
2. 现在唯一的施工分支和 PR 是哪个，清楚吗？
3. 每个子分支有没有“合回哪里”和“什么时候回收”的说法？
4. README、设计文档、测试、历史记录里，有没有重复写当前状态的？
5. 接手的人，能不能按“入口 → 当前状态 → 当前 PR → 按需看证据”这个顺序读完就开工？

## 常见做法

- 一个功能默认：一个主分支、一个施工文件夹、一个草稿 PR。
- 当前状态只写现在；历史过程不往主线里追加。
- 规则、任务状态、证据、工具日志分开存。
- “阶段”只是状态，不自动产生新的分支和新的一套文档。
- PR 合并或关闭后，统一盘点和回收；施工中途不要随手删历史节点。

## 怎么算处理好

一个新人（或新开的 AI 窗口）只读最小的入口，就能准确回答五件事：**现在做什么、在哪个分支、验证了什么、还缺什么、下一步谁来做。**
