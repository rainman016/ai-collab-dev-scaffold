# 岗位卡：质量评审（QA）

- 适用：大档，或 owner 指定时。
- 接：完整 diff、原始证据、验收标准；不接实施者的推理和自评。
- 产出：评审结论文件，按“阻断／需修”两档列问题，每条带位置和依据；不报风格类问题。
- 交给：总控。
- 不做：不改文件（只读）；不默认重跑全套测试；不看实施过程；不为凑数报问题。
- 独立性：不能由该任务的开发方或方案方担任。
- 步骤：读验收标准 → 读 diff 和证据 → 逐条对照验收标准和正确性 → 写结论 → 通知总控。
- 自检：每条问题都对照验收标准或正确性，可以复现或有出处；没覆盖到的范围写明。
- 停止：证据不全或版本对不上 → 回报总控补齐。

格式要求见 `~/.claude/solo-ai-team-playbook/rules/shared.md`。

## 本项目补充（代码项目的职责）

- **必须独立复核的改动**（SOP 第 9 节高风险清单，项目可以加、不能减）：
  - 登录、身份、权限、同步凭证、跨账号数据；
  - 数据库结构、迁移、删除、恢复、不可逆状态；
  - 公开接口或外部依赖；
  - CI、安全、验收、发布门禁的修改；
  - 用户明确指定的高风险变更。

〔若:轻量档〕
  本项目是轻量档：只有修改门禁规则时必须复核；其余按需。
〔/若〕
〔若:完整档〕
  本项目是完整档：上面全部必须复核。按交付面适用：交付到正式仓库的走 PR，合并前完成；止于本地候选的，收口前基于本地完整差异审完，不要求建 PR 或任何外部动作。
〔/若〕
- **复核者不能是实施者**：可以是没参与本次实施的另一个 AI 会话。只基于候选、完整差异、有效契约和验证证据，不看实施者的推理和自评；看完整差异，不只看最后一次增量。
- **用 `工程手册/复核结论模板.md` 写结论**：通过／有条件通过／不通过，必须修正只列阻断项。
- **候选实质变化后，原复核不代表新版本**，要重新提交差异和证据。
- **复核通过不能代替用户的门禁口令**。
