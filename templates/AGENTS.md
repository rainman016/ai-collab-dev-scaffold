## 3. 硬边界

- **不读密钥类文件**（环境变量文件、凭据和 secrets 文件、含 Key／令牌／连接串的配置、AI 工具认证和设置里的环境变量段）：路径可以看，内容不读；误读到了不复述、不写进任何文件，立即告诉用户去轮换。部署凭据同样不读不记。
- **门禁一道一道单独说口令**，“可以／继续／好的／审核通过”都不算；**门禁只由总控执行**，推送、合并、同步远端、部署都要用户说了对应口令（第 4 节）；团队模式 AI 不合并、不推主线。
- **花钱、碰生产、对外发布、不可逆的动作，要用户明确授权**；已有授权在其范围内持续有效（记在总览“持续授权与约束”），范围内连续推进，其余新动作再说一次。
- **没在《当前任务总览》登记的施工区不施工；不在正式工作区和只读基线里开发。**
- **不改写主线历史、不强推、不删远端分支；同步主线用合并，不用变基。**
- **没亲眼看过的写“未验证”**；回报带精确版本和证据路径。
- **每个候选先跑检查命令且通过**，不跳过、不为全绿删断言或放宽标准；治理区提交前跑 `项目文档/工程手册/文档体检.sh`，退出码 0 才提交。超限只能移走，不许删没处理完的反馈和授权。
- **规则文件的修改**：门禁类规则（交付规则第 3、4 节、本节）的修改必须由非实施者复核，复核通过前不生效。
- **搭建和嫁接阶段不改源码仓库里被版本管理的文件和仓库配置**（hooks、分支保护、CI、仓库自己的 `AGENTS.md`）；规则生效后，已授权的任务在登记过的施工区正常改代码。
〔若:已有项目〕
- 仓库自带的治理优先，冲突按《当前状态》“嫁接记录”处理；撤回按《当前状态》第 6 节的新增清单。
〔/若〕
- **Codex 等施工工具在施工文件夹里读不到本文件**：每份施工指令第一行都写“先读 `AGENTS.md`”，并附第 1 节治理区的绝对路径。

## 4. 门禁口令

〔若:个人完整〕
自动验证（AI 自己跑）→ 手测（用户说结果）→ “确认发布候选” → “确认合并” → “确认同步远端” → “确认部署”。六道互不替代；走 PR 合并要同时有“确认合并”和“确认同步远端”。
〔/若〕
〔若:个人轻量〕
自动验证 → 手测 → “确认合并” → “确认同步远端”。手测通过的那一版就是候选；没上线就没有部署，要上线先升到完整档。
〔/若〕
〔若:团队模式〕
自动验证 → 手测 → “确认发布候选”（总控推施工分支、建 Draft PR）；之后完整 CI、验收、合并、发布归仓库负责人。
〔/若〕

细则见《交付规则》第 3 节。
