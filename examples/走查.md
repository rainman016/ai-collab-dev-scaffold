# 走查：从搭建到第一次部署（虚构项目“冰箱便签”）

> 给想知道“脚手架到底怎么用、每一步会产出什么”的人看。项目、人、日期、提交号、主机、路径都是**虚构**的。规则以 `搭建指令.md` 和 `templates/` 为准，这里只演示落地后的样子。
> 设定：新项目、个人模式、完整档、有 Codex 施工、单窗口（总控由 Claude 担任）。

## 1. 起点和起步问题

项目文件夹 `~/work/fridge-note/`：空的，只有用户随手写的 `想法.txt`。用户说：“照 `搭建指令.md` 给这个项目搭结构。”

总控只列目录：没有源码和 `.git` → **新项目**。发问前先跑 `git config user.name`／`user.email`，本机已配好，不用问身份。总控把 8 条起步问题一次发出（一条一行，“问题｜推荐”），用户回：“第 3、4 条改，其余全按推荐。”

| # | 问题 | 用户的回答 |
|---|---|---|
| 3 | 技术栈和源码目录 | TypeScript＋Node.js＋SQLite，源码放 `src/` |
| 4 | 上线了没有？有登录吗？有持久数据吗？ | 未上线；**有登录**；**有持久数据** → 完整档 |
| 5 | 有没有另一个 AI 工具施工 | 有，Codex |
| 6 | 合并权在谁 | 只有我能合 → 个人模式 |
| 8 | 会不会多窗口 | 不会 → 单窗口 |

其余按推荐。总控回一句：“我会这样搭：治理区（规则和任务记录）＋ `main/`（源码仓库）＋ `worktrees/fridge-note-main/`（只读基线）。”不再等确认，直接做。

## 2. 搭出来什么

治理区 `git init`，先挂提交关口，建 `main/`（一个空提交 `e41d0a7`）和只读基线，按搭建指令附录 A 生成 17 个模板对应的文件，自检，本地提交（`b72e5d1`，体检在提交时通过，没有远端、没有推送），再手跑一次体检，退出码 0。

```text
~/work/fridge-note/                ← 治理区（一个 git 仓库，只本地提交）
├─ AGENTS.md  CLAUDE.md  .gitignore
├─ main/                           ← 正式工作区
├─ worktrees/fridge-note-main/     ← 只读基线
└─ 项目文档/
   ├─ 交付规则.md  文档规则.md  岗位速查.md
   ├─ 工程手册/  复核结论模板.md  推送前扫描.md/.sh  文档体检.sh  文档上限.json
   └─ 任务记录/
      ├─ 当前任务总览.md   协作治理/当前状态.md   模板/（施工指令、施工回报）
      └─ 任务01 项目架构梳理/  任务说明.md  当前状态.md
```

没建的：任务 02 以后的目录、施工区文件夹、`架构梳理.md`（任务 01 的产出）、`HANDOFF.md`（不用）。

## 3. 三件必读文件（节选，占位符已填）

**`AGENTS.md`**（约 2,000 字）：

```markdown
# 冰箱便签｜AI 入口（AGENTS.md）
> 脚手架版本：v2.0｜档位：完整｜模式：个人
> 规则状态：未生效（用户说“确认规则生效”后才生效）。未生效时：只做搭建和任务 01，不开施工线。
| 检查命令 | `npm run check` | 全量检查；没定写“待定”，任务 01 补齐 |
## 3. 硬边界（节选）
- 门禁一道一道单独说口令，“可以／继续／好的／审核通过”都不算；门禁只由总控执行……
- 每份施工指令第一行都写“先读 `~/work/fridge-note/AGENTS.md`”。
```

**《当前任务总览》**开头三行：`总控会话：无（单窗口，不发通知）`｜`上一棒：无（首个窗口）`｜`施工指令和回报放：项目文档/任务记录/<任务名>/`；下面是任务表、持续授权与约束、施工区登记、运行资源与迁移号、最近完成。

**任务 01 的《当前状态》**：六段，“唯一下一步”写“读最少的材料，写 `架构梳理.md` 草稿，交用户逐项确认”。

汇报（给用户，大白话）：“搭好了。要你做的：补全《当前状态》第 4 节；备份仓库什么时候建、什么时候首次推送，你单独说。**规则现在没生效**，你说一句‘确认规则生效’才生效。下一步我开始任务 01。”

用户说：“确认规则生效。”总控确认工作树干净，把《当前状态》第 2 节改成已生效并填提交号和原话，`AGENTS.md` 里“规则状态”那行也改掉，提交。

## 4. 任务 01：项目架构梳理

按 `任务说明.md` 做 8 项：产品边界、模块、旅程、流转、数据主来源、不做什么、可手测验收，加第 8 项“检查现状与缺口”（项目还没有代码：检查命令写“待定”，缺口是“没有全量命令”，由第一条施工线补）。总控只读了 `想法.txt`，一次只问一个关键问题（“同时放多少件食材？”——“三四十件，多时六十”），草稿本地提交一次，请用户逐项确认 4 个取舍点，用户回“全部按推荐”，每项记一行原话和日期。

收口：当前状态覆盖成一段结论，只留 `架构梳理.md` 最终版，总览“最近完成”记三个数：拍板 1 次、返修 0 轮、越权或被推翻 0 次。

## 5. 任务 02：第一条施工线

目标：注册登录＋食材增删查＋检查命令 `npm run check`（补齐任务 01 第 8 项的缺口）＋部署脚本；交付面：已部署版本。

1. 定档：“→ 大档，含登录，命中高风险清单。”产品经理角色出方案摘要，用户回“按摘要做，3 条取舍都按推荐”，才算方案确认。
2. 总控在总览登记施工区 `fridge-note-task-first-slice`、端口 3100、迁移号 001，提交治理区（体检通过），再建文件夹：`git -C main worktree add ../worktrees/fridge-note-task-first-slice -b fridge-note-task-first-slice e41d0a7`。
3. 总控按模板写施工指令，第一行“先读 `~/work/fridge-note/AGENTS.md`”，派给 Codex；Codex 写回报，第 1 轮版本 `c4d81f6`。

## 6. 六道门禁

| # | 门禁 | 用户说什么 | 总控做什么 | 证据（任务目录下） |
|---|---|---|---|---|
| 1 | 自动验证 | 不用说，AI 自己跑 | 重跑 `npm run check` 全绿；独立复核会话另出《复核结论》 | `证据/自动验证-c4d81f6.log` |
| 2 | 手测 | 说结果 | 先给齐五样（入口、版本、改了什么、清单、已知限制） | `证据/手测记录.md` |
| 3 | 发布候选 | “确认发布候选” | 跑推送前扫描（退出码 0）→ 推分支、建 PR，**不**合并 | `交付回执.md` |
| 4 | 合并到本地主线 | “确认合并” | 合并（不变基），在合并后的主线重跑检查 | 合并提交 `6a07fd3` |
| 5 | 同步远端主线 | “确认同步远端” | 核对本地和远端主线关系再推 | 回执写两边提交号 |
| 6 | 部署 | “确认部署” | 先发部署前回执（版本、范围、回滚路径），再运行部署脚本；不读部署凭据 | 部署前后两份回执 |

- **第 1 道**：独立复核给“有条件通过”：登录失败时“邮箱不存在”和“口令错误”提示不同，能探测已注册邮箱，而施工指令明明要求同一句提示。Codex 返修一轮（`d90b2e7`），**候选变了，原复核不代表新版本**，复核会话按完整差异重审后改为“通过”。
- **第 2 道**：用户回“手测通过，注册、加三条食材、过期标红都正常”才算；只说“看着可以”不算，总控会追问。
- **第 3 道前**：推分支要有远端。用户自己建空私有仓库并说“接入这个远端，含推空主线”（首次接入的授权必须含空初始提交 `e41d0a7`，记进《当前状态》第 3 节）；总控填好扫描脚本开头 4 项，先扫空主线、再扫施工分支，都是退出码 0 才推。
- **第 6 道后**：线上 `/healthz` 返回 `6a07fd3`，用户在线上注册一个测试账号、加一条食材，原话“线上能用”写进回执；线上验证做完才收口。

## 7. 收口

用不带强制的命令退出施工文件夹和本地分支，总览注销登记；施工指令、回报、过程稿移进 `任务记录/归档/`，任务目录只留最终方案、复核结论、交付回执；跑 `文档体检.sh` 通过后才标“已交付”，记三个数：拍板 6 次、返修 1 轮、越权或被推翻 0 次。《当前状态》第 4 节补上线上数据文件的位置（只写位置）和“部署凭据：有”。治理区备份仓库仍要用户另行授权，首次推送前先扫描。

**哪些是虚构的**：项目名、日期、提交号、路径、主机、用户的每一句原话、复核发现的问题。
